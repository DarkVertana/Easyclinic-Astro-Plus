Opening a second branch shows an owner how much of the first clinic ran on their being there. At one clinic you see the queue and you count the till. At two or more, you see what the branch managers tell you and what the figures show, and the rest has to run on rules everyone knows.

This guide covers the management side of running several branches: what head office holds, who runs each branch, what to measure and how to check. The software side is on the [clinic chain page](/solutions/clinic-chain/).

## Decide what head office holds and what each branch decides

Before the second branch opens, write down which decisions belong to head office and which stay at the branch. Anything a patient should find the same at every door belongs to head office. Anything that depends on the branch's own doctors and neighbourhood stays local.

| Head office sets | Each branch decides |
| --- | --- |
| Clinical SOPs | Appointment slots |
| The price list for each branch | Doctor timings |
| The formulary the pharmacy dispenses from | Staff and shifts |
| Note and prescription templates | Local promotions |

A split that is not written down gets decided case by case, by whoever is in the room. Revisit it once a year, or sooner when a branch keeps asking for the same exception.

## Write SOPs for the jobs every branch does

A standard operating procedure (SOP) is what makes a branch run the same way when the owner is not there. Start with the desk and the counter, which every patient passes through:

- Registering a new patient, and finding a returning one.
- Booking appointments and fitting in walk-ins.
- Raising the bill and closing the till at the end of the day.
- Dispensing, and the weekly count of costly stock.

Each SOP should fit on one page and be written with the staff who do the job. Put a date and an owner on every one, so a branch can tell whether it has the current version.

Clinical SOPs, for pathways such as the diabetes review, need a clinician to own them. The post on [clinical governance for clinic chains](/clinical-governance-software/) covers how to write and track them. For the stock count, see [medicine pilferage in clinics](/clinic-inventory-management-system/).

## Put one accountable manager in each branch

Every branch needs one named person who can decide on the day, for example when a doctor calls in sick or a delivery comes in short. That person answers to head office for the branch's numbers. In a small branch it may be the lead doctor or the senior receptionist, as long as everyone knows it is them.

Before a manager takes over a new branch, have them work at the first clinic for a while, so they learn the SOPs where they were written. After that, hold a fixed weekly call between head office and the branch managers, and give the managers a say in the SOPs. A manager who helped write a rule has a reason to keep it.

If you reward branches, reward them on the numbers every branch is measured on, so the target is the same for all of them.

## Cross-train the staff between branches

When a receptionist is on leave, a branch with nobody to cover slows down. Train staff so that someone from another branch can step in. Cover works only if the desk runs the same way at both branches, which is where the SOPs pay for the time they took to write.

Keep one channel for changes. When an SOP or a price changes, every branch hears it on the same day and in writing, so no branch finds out from a patient.

## Compare every branch on the same numbers

Pick a short list of numbers and look at them for every branch each week. The comparison is what matters: a branch far from the others on one number is where to look first.

| Number | What it tells you |
| --- | --- |
| Revenue by branch | Whether the branch is growing, and how it compares with branches of its size |
| Collections against billing | Whether what was billed was collected |
| Patients per doctor per hour | Whether the rota fits the demand |
| Waiting time | How long patients wait from arrival to the consult |
| Missed appointments | Whether reminders and follow-up calls are working |
| Stock written off | How much stock expired or went missing |
| SOP adherence | Whether the branch follows the clinical SOPs |
| Patient feedback | What patients say about the branch, month by month |
| Staff turnover | Whether the branch keeps its people |

These numbers mislead when each branch counts them differently. If one branch counts a follow-up as a visit and another does not, the comparison is wrong before anyone reads it. Every branch needs to count the same way, which is easiest when every branch records its work in the same system.

On Easy Clinic's Premium and Enterprise plans, every branch bills in the same system, so revenue for each branch and for the group is on the dashboard as the bills are raised, and reports run across locations. Some numbers on the list, such as staff turnover, will still come from your own records.

## Audit each branch every quarter

Once a quarter, someone from head office visits each branch with the same checklist:

- A sample of patient records, read against the clinical SOPs.
- Hygiene, and the handling of medical waste.
- The stock on the shelf, counted against the system.
- The cash close for a few recent days.
- The licences and registrations the premises needs, with their renewal dates.
- Patient complaints since the last visit, and what was done about each.

Agree the changes with the branch manager before you leave, and check them at the next visit. The same checklist at every branch is what lets you compare them.

## Where software helps, and where it does not

Software helps with the parts that depend on information. With every branch in one account, a patient has one record wherever they are seen, and a doctor who works at two branches has one login. Head office reads the figures each branch entered without waiting for an evening message.

It does not choose a branch manager, and it does not make staff follow an SOP. It also needs a connection. Easy Clinic is cloud software and does not run fully offline today, so each branch needs a working internet line and a backup, such as mobile data on a spare phone.
